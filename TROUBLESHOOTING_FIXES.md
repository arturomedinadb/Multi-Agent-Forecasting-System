# Schema Mapper Troubleshooting - Fixes Applied

## Problem Summary

The schema mapping workflow was failing with the following errors:

1. **JSON Parsing Error**: `JSONDecodeError: Expecting ',' delimiter: line 1 column 3471 (char 3470)`
   - The target schema JSON (3906 characters) was being corrupted near the end (at char 3470)
   - This caused the evaluation agent to fail repeatedly

2. **Infinite Loop**: The workflow hit max turns (100) because it kept retrying the same failing operation

3. **No Mapped CSVs Generated**: As a result, 0 mapped CSVs were being written

4. **Mapping Format Mismatch**: The prompt template was telling the agent to create a flat list of mappings, but the function expected mappings grouped by source file

## Root Cause

The issue was in the JSON parsing logic within `src/mapping_system/schema_mapping/tools/functions.py`:

1. The `_extract_first_json()` function was doing **double JSON encoding** - it would parse the JSON and then call `json.dumps()` on it, only to have the caller call `json.loads()` again
2. The `_sanitize_json_string()` function was too aggressive, removing ALL control characters including legitimate newlines and tabs
3. No fallback mechanism existed for malformed JSON generated by the LLM
4. Limited error diagnostics made it hard to debug

## Fixes Applied

### 1. Fixed Double JSON Encoding Issue
**File**: `src/mapping_system/schema_mapping/tools/functions.py`
**Function**: `_extract_first_json()`

**Before**:
```python
def _extract_first_json(json_str: str) -> str:
    obj, end_idx = decoder.raw_decode(json_str)
    return json.dumps(obj)  # ❌ Re-encoding here
    
# Caller code:
target_schema = json.loads(_extract_first_json(cleaned_schema))  # ❌ Double parsing
```

**After**:
```python
def _extract_first_json(json_str: str):
    obj, end_idx = decoder.raw_decode(json_str.lstrip())
    return obj  # ✅ Return parsed object directly
    
# Caller code:
target_schema = _extract_first_json(cleaned_schema)  # ✅ Single parsing
```

### 2. Improved JSON Sanitization
**Function**: `_sanitize_json_string()`

**Before**:
```python
# Removed ALL control chars including newlines/tabs
return re.sub(r'[\x00-\x1F\x7F]', ' ', json_str)
```

**After**:
```python
# Only remove truly problematic chars, keep \n, \t, \r
return re.sub(r'[\x00-\x08\x0B-\x0C\x0E-\x1F\x7F]', '', json_str)
```

### 3. Added Robust Error Handling
**Function**: `_extract_first_json()`

Now includes:
- Multiple parsing attempts with automatic fixes for common JSON issues
- Removal of trailing commas
- Quote normalization
- Detailed error logging with context around the error position
- Graceful fallback to empty dict instead of crashing

### 4. Added Debug Logging
**Function**: `evaluate_column_mapping_agent()`

Added logging to help diagnose issues:
```python
print(f"DEBUG evaluate_column_mapping_agent: Parsing mapping_plan_json (length: {len(mapping_plan_json)})")
print(f"DEBUG evaluate_column_mapping_agent: Parsing target_schema_json (length: {len(target_schema_json)})")
```

### 5. Fixed Mapping Format Mismatch
**File**: `templates/prompt_sets/v1/column_mapping_user.j2`

The prompt was instructing the agent to create a flat mapping structure, but the function expected a nested structure grouped by source file.

**Before** (Incorrect):
```json
{
  "mappings": [
    {
      "source_column": "date",
      "target_column": "date",
      "confidence": 0.95
    }
  ]
}
```

**After** (Correct):
```json
{
  "mappings": [
    {
      "source_file": "C:/path/to/file.csv",
      "mappings": [
        {
          "source_column": "date",
          "target_column": "date",
          "confidence": 0.95
        }
      ]
    }
  ]
}
```

This ensures the `generate_mapped_csvs` function can properly match mappings to their source files.

### 6. Fixed Windows Path Escaping in merge_mapped_csvs_to_target
**File**: `src/mapping_system/schema_mapping/tools/functions.py`
**Function**: `merge_mapped_csvs_to_target()`

Added path normalization before JSON parsing to handle Windows backslashes:

```python
# Before parsing JSON, replace backslashes with forward slashes
if isinstance(mapped_outputs_json, str):
    cleaned_json = mapped_outputs_json.replace('\\', '/')
    raw = json.loads(cleaned_json)
```

This prevents `JSONDecodeError: Invalid \escape` errors when paths like `C:\Users\...` are included in the JSON.

### 7. Fixed Mapping Key Mismatch Issues
**File**: `src/mapping_system/schema_mapping/tools/functions.py`
**Function**: `run_generate_mapped_csvs()`

**Problem**: The LLM was using different key names than expected:
- Using `"columns"` instead of `"mappings"` as top-level key
- Using `"source"` instead of `"source_file"` for file paths

**Fix**: Made the function accept both variants:

```python
# Accept both "mappings" and "columns" as valid top-level keys
mapping_entries = mapping_payload.get("mappings") or mapping_payload.get("columns", [])

# Accept both "source_file" and "source" as valid keys
source_path = entry.get("source_file") or entry.get("source")
```

This makes the system more robust to LLM output variations while we also strengthen the prompts.

### 8. Enhanced Orchestrator Instructions
**File**: `templates/prompt_sets/v1/orchestrator_user.j2`

Strengthened instructions to prevent orchestrator from calling tools directly:
- Added explicit statement: "You have NO tools of your own"
- Made FIRST ACTION REQUIREMENT more forceful
- Emphasized coordinator vs doer role

### 9. Added Comprehensive Debug Logging
**Files**: 
- `src/mapping_system/schema_mapping/run_workflow.py`
- `src/mapping_system/schema_mapping/tools/functions.py`

Added detailed logging to track:
- Workflow initialization
- Message flow and handoffs
- Mapping structure and keys
- File path matching attempts
- JSON parsing steps

This helps diagnose issues quickly without needing to inspect the database.

## Technical Details

### Why Character 3470?
- Target schema JSON is 3906 characters
- Error at position 3470 is near the end of the schema
- Likely cause: LLM echoing/manipulating the schema and making syntax error
- Common issues: trailing commas, unclosed brackets, quote mismatches

### Why It Kept Looping?
- Evaluation agent failed to parse JSON
- Returned error result
- Orchestrator retried the operation
- Same malformed JSON generated again
- Repeated until max_turns (100) reached

### Why 0 Mapped CSVs?
- Mapping evaluation failed
- No valid mappings confirmed
- `generate_mapped_csvs` skipped processing
- Empty results propagated through workflow
